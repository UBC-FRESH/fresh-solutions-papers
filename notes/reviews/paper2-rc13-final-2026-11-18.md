## Confidential comments to the editor

The scientific core is sound and should not be rejected. I independently verified every headline number against the committed evidence, confirmed all 65 manifest file hashes and the JORS PDF/TeX/supplement hashes against the tag tree, with the two PDFs also matching the release assets, and replayed all panels from a clean checkout of `p14-evidence-rc13`: 40 framework + 20 deep TSP, 200 QAP, 200 BLS, 100 TSP, 40 generic, 1,060 broad, with 25 `esc8` skips and five `brazil58` cap hits. The blockers are public-package reproducibility and provenance: the release’s own replay asset clones the stale default `main` (P12.1, “DO NOT SUBMIT”), which silently replays an older 60+20 evidence set; the manifest status names a nonexistent `p16-evidence-rc13` and still identifies the old working/JoH files as the manuscript; the submission README still carries literal placeholders. Once the tagged checkout is the documented path and the provenance strings are corrected, the manuscript is otherwise ready.

## Summary

The manuscript is a credible JORS Issues in Research Software experience report: it describes the adapter contract, resident state and replay gate, QAP/TSP reference adapters, a convergence-controlled QAP framework check, a 20-instance QAP/BLS panel, a frozen mixed-depth TSP panel, broad screens, external LKH context, a generic negative result, and a candid limitations section. The negative results and scope discipline are strengths: the tabu reference is explicitly unvalidated and BLS is primary; the TSP panel is explicitly frozen/mixed-depth; the generic layer is a negative result, not a promoted method.

The statistics match the evidence. QAP tabu mean 0.30085%, BLS 0.09614%, paired difference −0.20471 pp, 15/16 non-tied instance means, 73/200 vs 161/200 optima. TSP mean 0.003945%, worst 0.18458%, 94/100 optima, 95/100 patience, five `brazil58` cap hits at the optimum. Framework CPU ratio 1.2390 (95% CI 1.1683–1.3098), with 40/40 patience stops, quality matches, and exact replays. The supplement’s QAP/TSP/framework tables and the `bur26` diversity table match the evidence. The cover letter is consistent with the manuscript on the cluster-by-instance interval and public-release status; its “one-command replay” sentence inherits the P0 issue. The build has no undefined citations or overfull boxes. JORS scope is good: 3,816 words is within the 3,000–4,000-word guidance, the paper has two heading levels, Vancouver numbered references, an abstract, and the expected declarations. The 8-page PDF is above the journal’s rough 4–6-page guide; that is a production risk, not a word-limit failure.

The manuscript is not submission-ready because the public replay/provenance package is wrong, even though the tagged tree itself is correct.

## Major comments

1. **P0 — The release’s documented one-command replay clones the wrong branch and silently reproduces the wrong evidence.** `paper2/REPLAY.md:4` and the identical release asset `paper2-REPLAY.md` say `git clone --recurse-submodules https://github.com/UBC-FRESH/fresh-solutions-papers` with no `--branch`. The repository’s default `main` is `04e533c` (P12.1), not the rc13 tag `b398642`; it has no `paper2/submission/jors`, its `paper2/README.md:3` says “DO NOT SUBMIT”, its submodule is `3aa241e`, and its `paper2/replay_all.sh` runs only the old 60+20 framework/deep-TSP replays and exits 0. A reader following the release’s own instructions therefore gets a different, older evidence set, not the paper’s 1,060 broad / 200 QAP / 200 BLS / 100 TSP / 40 generic panels. The tag itself is correct: `p14-evidence-rc13` → `b398642`; the JORS PDF (`4cb0ae89…`), supplement (`38f17fab…`), `.tex` (`00ae875a…`), and supplement `.tex` (`987266ad…`) match the tag tree, and the two PDFs match the release assets; a clean `--branch p14-evidence-rc13` checkout with mounted QAPLIB/TSPLIB replays all panels exactly. **Action:** pin `--branch p14-evidence-rc13` (and submodule `4583ad3`) in `paper2/REPLAY.md` and the release asset; add the tag/checkout context to the manuscript’s replay paragraph; make `main` current or add a prominent tag checkout; add a commit assertion to `check_evidence.py`; re-cut the release.
2. **P1 — The manifest/release identity names a nonexistent tag and still points at obsolete files.** `MANIFEST:200` says `"public release candidate p16-evidence-rc13"`; no such tag/release exists (HTTP 404), while the public tag is `p14-evidence-rc13`; the repository root README and the GitHub release display the same P16 label. `MANIFEST:201-208, 223-230` still labels `paper2-manuscript.*` and `paper2-sn-jnl.*` as `manuscript`/`pdf`/`submission_*`; the JORS entries were added separately. `RELEASE-CANDIDATE.md:13-20` lists the obsolete JoH variant and omits the supplement `.tex`. The JORS file hashes and all 65 manifest file hashes pass, so this is an identity/provenance defect, not a hash failure, but a reader cannot tell which manuscript the candidate identifies. **Action:** set status to `p14-evidence-rc13`; point `manuscript`/`pdf` at the JORS files (or label them working vs submission); remove the JoH variant from the JORS asset list; re-cut.
3. **P2 — The submission README still contains literal placeholders and stale blockers.** `paper2/submission/jors/README.md:35-36` still has `[repository URL to be supplied at release]` and `[DOI to be assigned]`, while `:40-41` says the repository and tag are public; `:43-71` mixes stale or ambiguous blocking issues: the CPU claim is explicitly scoped in the manuscript, the tabu diversity table now exists in the supplement, and the remaining provenance-identity item is the P1 manifest/tag mismatch. The README is not the manuscript, but it is the package’s map and contradicts the artifact. **Action:** replace placeholders with the public URLs and “DOI pending”; update/remove the stale blocker list.

## Minor comments

- **Length/page guide.** 3,816 words is within JORS’s 3,000–4,000-word guidance, but the PDF is 8 pages (6 text + 2 references) against the journal’s rough 4–6-page guide. This is a production risk, not a word-limit failure; do not cut below 3,000 words. If the editor enforces the page guide, move Table 2 or broad-screen detail to the supplement (`MS p1, p5–7`; `README:21-24, 69-71`).
- **Public working README still contradicts the manuscript.** `paper2/README.md:81` says BLS is stronger on 14 instance means; the 10-seed manuscript/data say 15 of 16 non-tied. `:119` says “Adaptive depth: 4 for n<100, 3 for 100<=n<150, 2 for n>=150”; the manuscript and supplement use a frozen panel with `ch130`/`ch150` at depth 4, `lin105` at 3, `d198`/`pr152` at 2 (`MS p1, p5`; `SUPP p3–4`). Update or remove the working-manuscript prose.
- **Stale/ambiguous package claims.** `paper2/submission/jors/README.md:75` says the main manuscript/evidence were not edited; rc13 did edit the JORS `.tex` and manifest, so the note needs scoping. `:37-39` refers to a lab byline/ORCID although the manuscript has an individual author. Correct these package notes.
- **SciPy sentence.** `MS p6` (`paper2-jors.tex:354-356`) says “It uses NumPy and SciPy for the independent QAP baseline.” The reported independent baseline is BLS, which uses NumPy; SciPy appears only in an unreported `quadratic_assignment` baseline. Clarify (“NumPy for the reference adapters; SciPy for the optional SciPy baseline”) or remove the SciPy clause.
- **Small text issues.** `MS p4` has “1.33 .” with an extra space before the period (`paper2-jors.tex:207-208`), and the BLS 15/16 result is stated twice in adjacent sentences (`:249-252`). Tighten.
- **Residual licensing/instance metadata.** The manuscript’s licence split is clear, but `CITATION.cff` declares MIT for the whole deposit while `LICENSING.md` splits code (MIT) from manuscript/evidence (CC BY 4.0), and `paper2/instances/README.md` gives source/owner URLs for all eight files but no explicit licence/permission statement. Reconcile before minting the DOI; not a reason to delay the manuscript review.
